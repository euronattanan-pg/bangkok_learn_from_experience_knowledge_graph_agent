# Local learning-from-experience PoC

A local-only web app for reviewing a transcript against the included LFE questionnaire, explicitly approving it, and writing a case to an existing Neo4j database. The backend also supports a read-only case search. Thai, English, and mixed text are accepted; audio transcription is not included.

## Local Python setup (Windows)

In PowerShell, from this PoC checkout:

1. Use Python 3.11 or newer. Run `python -m venv .venv`, then `.\.venv\Scripts\python.exe -m pip install -r requirements.txt`. The official `microsoft-copilot-sdk` Python package is pinned to 2.0.0.
2. If `.env_dev` does not already exist here, run `Copy-Item .env.example .env_dev`. Open `.env_dev` in a local editor and set `NEO4J_URI`, `NEO4J_USERNAME`, `NEO4J_PASSWORD`, and, if needed, `NEO4J_DATABASE` (defaults to `neo4j`). **Rotate any password previously sent in chat and use the replacement. Never paste credentials into chat or commit this file.** Use the encrypted URI provided by the database service where available. Use dotenv syntax and single-quote values containing special characters such as `$` or `#`.
3. If `.env` does not already exist, copy `.env.example` to `.env`. Keep `LFE_MODEL_PROVIDER=manual` for manual use. To opt in to local Copilot, install the official Copilot CLI (`winget install --id GitHub.Copilot --exact`), run `copilot login` in a local terminal and complete its browser/device authentication, then set `LFE_MODEL_PROVIDER=copilot-local-cli` in `.env`. Keep `LFE_COPILOT_AUTH=local-cli`; set `LFE_COPILOT_MODEL=auto` or choose a model ID available to that signed-in account. Do not put a token or password in `.env`.
4. Stop any existing preview using port 8000, then run `.\.venv\Scripts\python.exe -m lfe.server --env-dev --env` and open <http://127.0.0.1:8000/>. This explicitly loads Neo4j settings from `.env_dev` and model settings from `.env`; process variables override file values, including empty values. If leaving model mode manual, the flags are still safe. Stop the app with Ctrl+C.
5. To activate local inference, start with `.\.venv\Scripts\python.exe -m lfe.server --env-dev --env --allow-local-copilot`. This additional opt-in is required every run; startup refuses non-loopback binds, non-local deployment mode, and explicit token/runtime identity overrides. The SDK's pinned runtime must already be cached; this app reports when it is missing and does not download it automatically. Local inference is single-user only; do not use it on a VM, behind a shared reverse proxy, in Docker, or for LAN testing.
6. Select **Check connection** in the app to run a read-only connectivity check. Before the first upload to a database, install graph constraints with `.\.venv\Scripts\python.exe -m lfe.init_schema --env-dev --confirm-database <database-name>`, replacing the placeholder with the configured database name. This requires permission to create constraints. The command does not migrate or delete data.
7. Create a questionnaire, enter a title, submit it, open it from **Pending approval**, review and approve it. In local Copilot mode, use **Pending upload** to generate and review the structured graph mapping, resolve any flagged entities in the questionnaire, and explicitly confirm the mapping before **Upload to Neo4j** becomes available. Manual mode keeps the existing deterministic mapping and explicit upload flow. The account needs write permission.

Mock uploads are disabled by default. Only after confirming `.env_dev` points to a dedicated test database, start the local app with `.\.venv\Scripts\python.exe -m lfe.server --env-dev --allow-mock-upload`. This is an operator assertion, not automatic detection of a test database: never use the flag against production. Approved mock cases remain explicitly uploaded one at a time and are marked `is_mock: true` in Neo4j. Restart without the flag to block mock uploads.

`.env` and `.env_dev` are Git-ignored and excluded from the Docker build context. Local `secrets/`, `credentials/`, `.copilot/`, netrc files and common private-key containers (`.pem`, `.key`, `.p12`, `.pfx`) are also excluded. Keep `.env.example` blank or placeholder-only. Ignore rules do not remove already-tracked files or detect credentials embedded in source; review staged changes before every push. Leave the values empty to explore without a database; no connection is attempted until a check, search, or approved write is requested. The backend alone connects to Neo4j. The app binds to `127.0.0.1`; do not expose this unauthenticated PoC to a LAN or public network. Drafts are stored locally under `data`; protect the machine and avoid inappropriate sensitive transcripts.

If a previous background preview occupies port 8000, run `Get-NetTCPConnection -LocalPort 8000 -State Listen` to identify its owning PID. Inspect that PID locally (for example, `Get-CimInstance Win32_Process -Filter "ProcessId = <PID>"`) and use `Stop-Process -Id <PID>` only after confirming it is the LFE preview.

## Docker alternative

With Docker Desktop installed, use `docker compose --env-file .env_dev up --build` and stop with `docker compose --env-file .env_dev down`. Docker stores drafts in a separate `lfe_data` volume, not the Python preview's local data. The file's values are passed to the backend container; the file itself is excluded from the image. Process environment variables can override Compose file values.

## Workflow and current limitations

1. Paste a transcript and create a draft. **Manual mode** does not call Copilot and starts every answer as null. In the explicit local Copilot mode, the pinned SDK returns only included questionnaire fields with typed values and short source excerpts; the backend rejects unsupported fields, invalid types, unsupported evidence, or any non-null answer without a verbatim transcript excerpt. Missing and unmappable values remain null. The human review and approval gate is unchanged. AI prompts and retrieved case summaries are sent to GitHub Copilot under the signed-in user's account and its applicable policies.
   Alternatively, select a prepared mock case and load it for review. Loading is temporary and does not create a draft until **Save review** is selected. Sample drafts are marked as mock; missing values remain blank and mock uploads require explicit test-database mode.
2. Save the review and submit it for approval. **Saved drafts** lists all saved, unsubmitted reviews so switching cases or restarting does not hide earlier work. An LFE title is required. Use **Preview graph mapping** on a saved review to inspect the proposed separated entities before approving; the preview does not read or change Neo4j. Review a submitted case from **Pending approval** before explicitly approving it. Saving edits to a pending or approved case returns it to draft and requires resubmission. Only an approved snapshot can be uploaded. The 18 included questions are numbered sequentially, with date/time as question 3 and safety/product quality impact as question 4; related answers are grouped under their question. Excluded questions are not captured. Cause confirmation is an optional reviewer-supplied distinction; an unconfirmed cause is not promoted to a ConfirmedCause node.
3. **Pending upload** shows approved case details and an explicit per-case upload control. With local Copilot enabled, the model proposes only typed entity lists for schema-known questionnaire fields; every proposed name and evidence excerpt must occur verbatim in its source answer. Unsupported fields, omitted values, duplicates, ungrounded text, and ambiguous/unmappable entities fail validation or are flagged for correction. The proposal is persisted against the case revision, audited without answer text, and must be explicitly confirmed; editing the questionnaire clears it and invalidates approval. The confirmed mapping is frozen into the upload snapshot. Copilot never writes Cypher or accesses Neo4j. The backend deterministically builds the graph and fixed parameterized Cypher, then writes a case and related nodes in one transaction. **Approved history** shows approved cases awaiting upload, uploaded cases, upload failures, mock cases and cases returned to draft. If an upload fails or the app is interrupted, its outcome may be unknown; the unchanged approved snapshot can be retried, but edits are locked after an upload attempt. A confirmed duplicate title is rolled back and returned to draft for correction and reapproval. Attachment links are stored as text, not uploaded. Drafts and status persist locally.
4. Search saved cases. In manual mode, the app uses a fixed, parameterized, read-only keyword search. In local Copilot mode, the SDK may return only a typed read plan (`field`, bounded search terms, and optional case ID); the backend validates it and compiles it to fixed parameterized Cypher with a 20-case limit. The model never emits or executes Cypher. Answers use only returned case properties and must cite a returned case ID; no matches are reported directly. This may miss matches, especially in unsegmented Thai. The response is a simple answer, not the as-yet unspecified answer template.

The **Audit trail** records lifecycle transitions, rejected actions, upload outcomes and UTC timestamps in the local SQLite store, without transcripts or credentials. The app has no authenticated user identity, so the actor is shown as unknown. The screen shows the latest 200 events; older events remain in the database. Existing cases are recorded as legacy imports rather than inventing past audit events. SQLite and Neo4j cannot be committed together; an interrupted upload is flagged as having an unknown outcome.

Startup takes an OS file lock on the SQLite workspace before recovering interrupted uploads and holds it for the server lifetime. A second app using that workspace refuses to start, even on a different port; a crashed process releases the lock automatically. Keep the lock file in place. Plain `Store` construction does not trigger recovery. Use a single app process on local disk, not multiple workers or a network filesystem; a multi-worker VM deployment will need database-backed job ownership instead.

The first upload freezes its full graph snapshot locally. Uncertain retries and their previews use that same snapshot and stable case ID, even after a mapping-code update. A graph fingerprint saved atomically with the case lets an already committed upload reconcile without rewriting nodes or relationships. A schema or duplicate rejection on an uncertain retry leaves it locked; it must not become editable. Older uncertain records without a frozen snapshot, or graph cases without a matching fingerprint, require explicit reconciliation rather than an automatic overwrite. Existing successfully uploaded cases do not need to be rewritten. Workspace controls are temporarily locked during mutations; failed uploads refresh both the queue and the matching open review without replacing another case or later edits. If an authoritative case refresh also fails, reopen the case successfully before editing or retrying; stale controls stay locked.

### Graph identity and reuse

LFE titles are unique after Unicode NFKC normalization, case folding, and whitespace normalization. Drafts are checked locally under a SQLite write lock; Neo4j also enforces unique case IDs and normalized title keys, including across app instances. Retrying the same case ID is idempotent. Local historical uploads marked **unverified after database reset** are retained for audit but do not reserve a title; the graph constraint remains authoritative for the target database. A database reset and local audit updates are separate operations and cannot be atomic.

Projects, products, lines, materials and suppliers are shared by exact normalized name within the database. Machines are shared only when the exact normalized machine name and line name match. Components are individual nodes shared only for the same normalized component, machine and line. Each component is also linked to its machine when exactly one machine is identified; with multiple machines, no assignment is guessed. Without unambiguous machine and line context, components remain case-specific. These are **reported-name references**, not verified master-data identities: no synonyms, SKU equivalence, site, supplier relationship, or physical asset identity is inferred. If identical names denote different entities, qualify the names in the questionnaire (for example with the site) before approval; there is no interactive entity-resolution mechanism. Product status/details are kept on the case-to-product relationship when there is one product; otherwise they remain on the case.

In the questionnaire, separate multiple project, product, line, machine, material or supplier names with semicolons or new lines. Components also split on commas and the word `and`; attachment names also split on commas. Separate distinct actions with semicolons or new lines. Double-quote a single name or action containing one of its delimiters, and double an embedded quote. Review the proposed mapping before approval: delimiters are not semantic understanding. The original answers and evidence are retained on the case or evidence nodes. Issues, defect descriptions, causes, impact details and verification are narrative occurrences and are not split on punctuation. Multiple attachment names are separate case-specific evidence nodes; a single link is not assigned to one name when the association is unknown. A case-level effectiveness answer is not attributed to every individual action when several actions are listed.

Node display names are title-cased and recognized acronyms such as LFE, SKU, RCA, EO, PLC, VAT, NPI and CTMZ-HU remain uppercase; the acronym list is maintained in `lfe/schema.py`. Original questionnaire text remains unchanged. Neo4j labels retain PascalCase and property keys remain snake_case.

**Existing graph migration:** databases containing cases created with the previous mapping, including combined component nodes, require a reviewed migration before using the new mapping. Local history created before mapping versions were recorded shows the upload's graph version as unverified, not upgraded. The new mapping requires component-node and component-link uniqueness constraints and rejects uploads while any older case is present. There is no automatic migration or cleanup command. Do not mix old and new app versions against the same database. Existing shared node display names are not overwritten on later matches. Installing constraints alone does not migrate old cases.

The project has no existing graph schema artifact or SDK configuration in this checkout. The mapping reflects the supplied questionnaire and node names; it should be checked against the authoritative latest chart before production use. Unknown cause status, action type, and other unavailable values are not invented. Relationships link each relevant entity directly to the case, rather than asserting relationships between entities that the questionnaire does not establish.

`lfe/model.py` isolates manual and local Copilot adapters. Transcript extraction returns the strict 18-question contract with evidence; graph mapping, available only for approved questionnaires, returns schema-limited reusable-entity candidates and evidence. Backend validation requires each candidate to be an exact substring of its own answer, records unresolved entities for reviewer correction, and rejects incomplete or malformed output. Each inference call creates a fresh `mode="coding-agent"` session so SDK v2 can resolve the signed-in CLI identity; the session explicitly sets `tools={"available_tools": []}` and disables config discovery, repository hooks, host Git operations, MCP, skills, memory and cross-session retrieval. There is no filesystem, shell, browser, MCP, or Neo4j tool access. Sessions have unique IDs and are deleted after the request, SDK telemetry is disabled for this local mode, and model requests have a bounded timeout. `auto` delegates model choice to Copilot; a configured model ID is checked against models returned for the signed-in account before use. Local CLI authentication failures are surfaced without returning SDK exception text, prompts, or credentials. The app does not read tokens from `.env`: if any supported token variable (`COPILOT_GITHUB_TOKEN`, `GH_TOKEN`, or `GITHUB_TOKEN`), `COPILOT_HOME`, or `COPILOT_CLI_PATH` is set in the process or model `.env`, local mode refuses to start rather than changing identity. Environment variables override ordinary model settings in `.env`; explicit auth/runtime overrides are conflicts, not precedence choices. This PoC uses one synchronous app service rather than a separate worker; there are no background model jobs.

The SDK's empty mode uses an explicit in-process runtime rooted at the signed-in user's default Copilot home (`~/.copilot`). The adapter checks for the SDK-pinned runtime before any request and fails closed instead of allowing the SDK to download runtime software implicitly. The API and UI show a clear unavailable status until that runtime is already present in the SDK cache.

## Shared VM and Copilot integration direction

The intended shared VM will authenticate users through P&G LDAP and expose a separate admin-only access-management page. These are **design requirements, not implemented authentication**: do not expose this PoC to other users yet. Use a server-verified LDAP identity over approved TLS/LDAPS, never trust browser-supplied identity headers, and retain no user LDAP passwords. Deny access by default. Separate intake, reviewer, uploader and admin privileges; authorize every API route server-side, isolate user/session state, revoke sessions when access changes, and audit admin grants/revocations with verified actor IDs and outcomes. Add HTTPS, CSRF/session protection and login rate limits before shared access. The admin page must not display inference tokens or accept self-elevation. LDAP connection settings, approved groups and bootstrap-admin policy still need organization configuration.

The eventual shared VM will use an organization-approved service credential, **not** a developer's personal CLI login. Local single-user testing now has a separate explicit `copilot-local-cli` mode using the official SDK 2.0.0 and credentials established by `copilot login` in the user's operating-system credential store. It is rejected for VM deployment mode, Docker, non-loopback binding, or explicit token/runtime identity overrides. It must not be reverse-proxied to multiple users. No GitHub token is accepted from `.env` by the local adapter. The organization service provider (`LFE_MODEL_PROVIDER=copilot`) remains unavailable until its supported auth/billing model is configured and independently implemented. Docker defaults to VM mode and continues to use manual inference; these changes do not mount or copy any host keychain into containers.

Official [Copilot SDK local CLI guidance](https://github.com/github/copilot-sdk/blob/main/docs/setup/bundled-cli.md) documents using credentials from `copilot login`; the [authentication guidance](https://github.com/github/copilot-sdk/blob/main/docs/auth/authenticate.md) describes OS-keychain storage and SDK discovery. The local adapter intentionally uses stored-user auth and fails on explicit tokens rather than silently selecting a different identity. For VM service deployment, the [server-to-server guidance](https://github.com/github/copilot-sdk/blob/main/docs/auth/server-to-server-tokens.md) describes organization-enabled GitHub App installation tokens with the **Copilot Requests** permission and organization-attributed billing. Those tokens require managed rotation; plain `.env` is not production secret storage. The [multi-user guidance](https://github.com/github/copilot-sdk/blob/main/docs/setup/multi-tenancy.md) requires isolated sessions and an empty tool baseline, not ambient coding-agent defaults. LDAP does not confer Copilot entitlement. User-scoped OAuth is a different option; BYOK is not a Copilot service token and requires separate approval. VM service inference is still disabled.

Transcript extraction now returns only the included questionnaire contract and evidence for strict backend validation and human approval. The approved questionnaire can be mapped to schema-known reusable entities; the user reviews and confirms that grounded proposal before upload. Q&A uses a typed, allowlisted read plan, compiled to fixed parameterized Cypher with bounded terms and result count; arbitrary model Cypher is never executed. Upload Cypher is also fixed/generated by the backend from the validated graph mapping, never by the model. The SDK receives no database credentials, shell tools, filesystem access, browser, or graph-write tools. On a shared VM, first implement P&G LDAP authentication and authorization, isolated per-user state, admin access management and audit; then enable an organization-approved Copilot auth/billing option. Use the approved secret store or service-account-only file permissions and protected backups, with rotation and redacted errors; never expose tokens in the browser, admin UI, logs or images. Keep `.env` for local model configuration only.

## Tests

Backend: `.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_workflow.py -v`.

For browser regressions, install `requirements-dev.txt` and run `.\.venv\Scripts\python.exe -m playwright install chromium`, then run `.\.venv\Scripts\python.exe -m unittest discover -s tests -v` for both suites. Alternatively, with Microsoft Edge installed, set `$env:LFE_TEST_BROWSER_CHANNEL='msedge'` instead of downloading Chromium. Tests fail explicitly if the selected browser is unavailable. Browser APIs and Neo4j connections are mocked; tests never require credentials or perform live graph writes.
